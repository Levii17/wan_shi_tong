01
Physical infrastructure

The biggest misconception about the internet is that it's an invisible "cloud." In reality, the internet is the largest physical machine ever built — millions of miles of cables and hundreds of millions of computers.

Clients
Your devices — phones, laptops, TVs. They request information.
Servers
Powerful computers storing websites, apps, and data. They serve information.
Data centers
Massive warehouses of servers. This is where the "cloud" physically lives.
Backbone cables
Subsea fiber-optic cables transmit data as light pulses across oceans.
Key insight

Fiber-optic cables use light to transmit data. A single cable can carry hundreds of terabits per second — enough to stream millions of 4K movies simultaneously.

02
IP addresses & DNS

If the internet is a giant postal system, every device needs an address so data knows where to go.

IP address
A unique number assigned to every device (e.g., 192.168.1.45).
DNS
Translates human-readable names (youtube.com) into IP addresses computers understand.
Analogy

DNS is like the Contacts app on your phone. You tap "Mom" and your phone dials her actual number — you never need to remember it yourself.

03
Packets & routing

When you request a 4K movie, the server doesn't send one giant file — that would clog every network.

1
Data is split into packets
Every file, video, or webpage is broken into small, equal-sized chunks called packets. Each gets a "shipping label" with the destination IP address and a sequence number.
2
Routers direct traffic
Specialized computers at network intersections read each packet's label and send it down the fastest available path.
3
Packets are reassembled
Your device uses the sequence numbers to reassemble the packets in the correct order.
Analogy

Mailing a built Lego castle: you disassemble it, mail each brick in a numbered envelope, and the recipient rebuilds it.

04
Protocols: the rules of communication

For a Mac to talk to a Windows PC, they all need to speak the same language. These standardized languages are called protocols.

Protocol Full name What it does
TCP/IP Transmission Control / Internet Protocol TCP guarantees all packets arrive and are ordered correctly. IP handles addressing and routing.
HTTP Hypertext Transfer Protocol The language for the World Wide Web — requesting and delivering web pages.
HTTPS HTTP Secure HTTP + encryption. Data between you and the server is scrambled. Intercepted packets look like gibberish.
UDP User Datagram Protocol Faster than TCP but no delivery guarantee. Used for video calls, gaming, DNS queries.
The journey of a click

You type netflix.com → DNS resolves the IP → your browser breaks the request into packets → packets travel through your ISP and subsea cables → Netflix's server sends back the page as millions of new packets → your browser reassembles and renders them.

05
Wi-Fi & the last mile

Data travels mostly through physical cables and light pulses until it reaches your home. Wi-Fi covers the final invisible gap between the wall and your device.

Your phone converts data to radio waves
Your device has a tiny antenna that translates digital data (1s and 0s) into radio wave frequencies — 2.4 GHz or 5 GHz.
The router catches and translates
Your Wi-Fi router receives the radio waves and translates them back into digital data.
The modem sends it into the cable
The modem pushes that data into the physical cable (fiber, coaxial, or copper), sending it toward your ISP.
Analogy

You're on an island and need to send a letter to the mainland. You use a flashlight to blink Morse code to a lighthouse keeper (Wi-Fi). The keeper writes it down and drops it into the postal system (physical cables).

06
Security, threats & encryption

Because Wi-Fi uses radio waves, it broadcasts outward in every direction — anyone in range can technically "hear" your data.

Threat: Packet sniffing

Hackers use specialized software to capture radio wave packets floating through the air.

Threat: Evil twin / MitM

A hacker broadcasts a fake Wi-Fi network; every packet passes through their machine first.

Modern encryption makes intercepted data useless, even when it's successfully captured.

Shield How it works
WPA2 / WPA3 When you enter a Wi-Fi password, you enable an encryption key that scrambles your radio waves before they're broadcast.
HTTPS Even on password-free public Wi-Fi, HTTPS encrypts your passwords and credit card numbers before they're put into packets. The lock icon confirms this.

How HTTPS scrambles your data: the TLS handshake

A
Asymmetric encryption — the padlock system
The server gives out a public key (can only lock data) to anyone who asks, and keeps a private key (can only unlock) secret forever.
B
Symmetric encryption — the secret handshake
Once a secure channel exists, both sides switch to a single shared key — much faster, needed for streaming 4K video.
Step What happens Who
1. Hello "I want to connect securely." Browser
2. Padlock "Here's my public key." Server
3. Secret Generates a temporary session key. Browser
4. Lock Seals session key inside a box locked with the public key. Browser
5. Delivery Sends the locked box (useless without private key). Browser
6. Unlock Opens the box with private key, reveals session key. Server
7. Secure Both sides now share the fast session key. Connection is live. Both
07
HTTP in depth
The request-response cycle

HTTP is the language browsers and servers use. Every interaction is a strict ask-and-receive: the browser sends a request, the server sends a response.

Analogy

Ordering at a restaurant. You give the waiter your order (request), and the waiter brings food from the kitchen (response).

HTTP methods — the verbs of the internet

GET
Fetches data. Visible in URL, like writing on a postcard.
POST
Submits data (passwords, forms) hidden in request body — like a sealed envelope.
PUT/PATCH
Updates existing data. PUT replaces, PATCH updates partially.
DELETE
Removes a resource from the server.

Statelessness & cookies

HTTP is "stateless" — the server retains zero memory of previous requests. This is why cookies exist: when you log in, the server gives your browser a tiny digital ID card so it recognizes you.

Status codes — the server's response signal

Range Meaning Examples
2xx Success 200 OK
3xx Redirection 301 Moved Permanently
4xx Client error 404 Not Found, 403 Forbidden
5xx Server error 500 Internal Server Error
Raw POST request (login form)
POST /login.html HTTP/1.1\nHost: www.example.com\nUser-Agent: Mozilla/5.0\nContent-Type: application/x-www-form-urlencoded\n\nusername=joesmith&password=secret123
Raw HTTP response
HTTP/1.1 200 OK\nDate: ...\nContent-Type: text/html\n\n<!DOCTYPE html><html><body><h1>Welcome back!</h1></body></html>

09
DNS caching & TTL

Caching is a digital cheat-sheet: once your computer learns an IP, it writes it down locally and skips the journey next time.

Layer Where Speed
1 Browser cache ~0ms
2 OS cache <1ms
3 Home router ~1ms
4 ISP Recursive Resolver ~10ms
TTL — the expiry date

Every cached record has a Time to Live (TTL) measured in seconds. When the timer hits zero, the cache deletes the record.

10
Web hosting

If the domain is your website's phone number, web hosting is the physical house where the website lives.

Shared

Apartment building

Hundreds of sites share one server. Cheapest, but traffic spikes can slow neighbours.

VPS

Private condo

Physically shared but digitally partitioned with guaranteed resources.

Dedicated

Private mansion

You rent an entire physical server. Maximum control.

Cloud

Shape-shifting hotel

Scales automatically; pay only for what you use (AWS, GCP, Azure).

How domains connect to hosting

Your host gives you two nameserver addresses (ns1.hostinger.com). Paste these into your domain registrar settings — this points the domain to your hosting server's IP.

Frontend vs backend — the full picture

Every file you upload belongs to one of two worlds. Understanding this split is the single most important mental model for web development.

Frontend
Client-side
Files are sent to the user's browser to be executed.
HTML — skeleton
CSS — styling
JS — behaviour
Backend
Server-side
Files never leave the server. They run there, process data, and send only the result.
Python/Node.js/PHP
Databases
APIs & logic
Restaurant analogy

The frontend is the dining room (menu, lighting, waiters). The backend is the kitchen — hidden, where the actual work happens.

CDNs — content delivery networks

A CDN places copies of your content at dozens of locations worldwide, dramatically reducing latency.

Origin server
Your actual hosting server — the single source of truth.
Edge nodes (PoPs)
Copies of static content (images, CSS, videos) cached worldwide — Johannesburg, London, Singapore.
Result — lower latency
A user in SA might wait 5ms instead of 200ms from California. Providers: Cloudflare, AWS CloudFront, Akamai.
What CDNs cache

Static assets — images, CSS, JS files. They don’t cache dynamic content (personalized feeds, account data).

14
APIs — how services talk to each other

An API defines rules for how two pieces of software communicate. Your weather app asks a weather API — it didn't build its own satellites.

Analogy

A restaurant menu is an API. It defines exactly what you can order and what you'll get back. You don't need to know how the kitchen works.

REST
Uses HTTP methods, returns JSON. Stateless.
GraphQL
Specify exactly which fields you need. Avoids over-fetching.
WebSockets
Persistent two-way connection. Live chat, stock tickers.
Webhooks
"Don't call us, we'll call you." Notifies your URL instantly when an event happens.
